Abstract

In interior design and custom furniture, every order comes with different dimensions, so drawings and 3D models are usually redrawn each time. To remove this repetitive work, I introduced parametric models that rebuild the shape by rule when the dimensions change, which cleared the bottleneck of redrawing every order. The parametric model itself, however, still has to be built by hand, rule by rule, and this becomes a bottleneck again whenever a new product type is added. This project tests whether an AI can build a parametric CAD model of a kitchen base cabinet from a single customer sentence. All 22 generated models followed the rules at the size the customer asked for, and 98% of 638 checks passed after resizing each model 30 times. The failing 2% was one hinge-side error that appears only when a cabinet has three doors, an error that cannot be found by checking only the requested size.

Tools: Python, CadQuery, Claude API, GitHub Actions (automated runs)

Code and results: github.com/goyodsgn/param-cabinet

Role: Problem definition, cabinet design rules, experiment design, review of results. Code written together with an AI coding tool

1. Introduction

1.1 Problem

Kitchen furniture is sized to the space it is installed in. Even the same base cabinet has a different width, height and depth for every order, so drawings and 3D models are usually redrawn whenever an order comes in. To cut this repetition, I started designing furniture as parametric models: entering the dimensions produces the shape, which removed the bottleneck of redrawing every order.

What is a parametric model: A 3D model that rebuilds itself by fixed rules when its dimensions (parameters) change. For example, making a base cabinet wider also adds doors.

The remaining bottleneck is building the parametric model in the first place. A single base cabinet has many rules for door count, hinge position, dividers, shelves and legs, and these rules depend on each other. A change in width changes the number of doors, and a change in door count changes the dividers and hinge sides. I have to define each of these relationships by hand and start over for every new product type. If an AI could do this step, the second bottleneck would shrink as well.

1.2 Research questions

To use an AI-made model as a parametric model in practice, three things need to hold.

  • RQ1. However a customer phrases the request, does the AI read the dimensions correctly and build the model by the rules?

  • RQ2. When a customer request conflicts with a manufacturing rule, does the AI resolve it in the defined order of priority?

  • RQ3. Does the model still follow the rules when other sizes are put into it?

RQ3 is the core of this project. A parametric model is built to be resized later, so a model that is correct only at the first requested size is not usable.

2. Related work

AI that turns text into 3D shapes falls into two broad groups. Mesh-generation AI produces shapes made of surface pieces (meshes), which cannot be used for physical production. CAD-code-generation AI (text-to-CAD) produces code that can be manufactured, but it is mostly evaluated on whether a single shape matches its description. Neither asks whether the rules still hold after resizing. This project uses CAD code generation for physical production and changes the evaluation criterion to that question.

3. Method

3.1 Subject: the base cabinet and its design rules

The subject is a kitchen base cabinet. Its doors, hinges, dividers and shelves change with size, and its outer form is simple, which makes it a good test of how well the parametric logic is implemented. The inputs are width (W), height (H) and depth (D), the final overall dimensions including doors and legs.

Terms used in the table:

  • Onset / inset: A panel laid over the edges of other panels is onset; a panel fitted between them is inset.

  • Door gap: The clearance between a door and the carcass, and between doors, so that doors do not hit each other given installation tolerances.

  • Shelf pin: A small pin that supports a shelf, inserted into holes drilled in the side or divider panel.

  • Inner wall: A vertical divider that splits the space behind the doors.

The rules have priorities. "No" in the table marks an absolute rule that must hold because of hinge load or manufacturing tolerance. It is kept even when the customer asks otherwise, and the reason is left as a note. Everything else is a company default that the customer can override by asking explicitly.

3.2 Tools

The CAD tool is CadQuery, an open-source CAD library that builds 3D shapes from Python code and exports STEP files that standard CAD software can open. Changing the numbers at the top of the code (width, height, depth and so on) and running it again rebuilds the shape. The code itself plays the role of the feature tree in a regular CAD program.

3.3 Procedure

Instead of checking the AI's models by eye, each one is compared automatically with a reference model.

Figure 1. Experiment flow. The key step is re-grading the generated model at many sizes.

  1. Build a reference model: A reference (answer) model with every cabinet rule was built first. Given a size, it computes how many doors and hinges are correct.

  2. Ask the AI: The AI (Claude Sonnet 5.5) receives the company rule document and the customer sentence and writes CadQuery code.

  3. Grade: The AI's code is actually run to produce the 3D shape, which is compared with the reference model on the 12 items below.

  4. Resize and grade again: The same code is run with 30 different sizes and graded each time. This checks that the model does not break when the customer later changes the dimensions.

The whole process runs automatically on GitHub Actions. Pushing code triggers generation, grading and preview images on the server.

5. Discussion

5.1 Findings

  • Given clear rules, the AI follows them well even when there are many rules and mixed customer requests.

  • A parametric model has to be verified across sizes. It can be right at one size and wrong at another.

  • Splitting the rules into "what the customer can change" and "what manufacturing cannot change" lets the AI reflect customer requests while keeping manufacturing constraints.

5.2 Limitations

  • The rules were given already written as formulas. In practice, rules are often not documented and exist only as the maker's know-how.

  • The subject is a single type of base cabinet; drawers and handles were not included.

6. Conclusion and future work

With clearly organized rules, the AI built resizable parametric base cabinet models from a single customer sentence at a 98% level. It also showed that checking a single size is not enough to judge whether a model is correct. Next steps:

6.1 Completing this experiment

  1. Automatic repair: Feed the failing cases back to the AI to fix, and see whether 98% can reach 100%.

  2. Web demo: Add sliders to the generated model so that dimensions can be changed and the shape seen directly on the web.

  3. Rules in plain words only: Give the rules the way a practitioner would say them instead of as formulas, shuffle their order, and measure how much accuracy drops.

6.2 Extending the scope

  1. Research direction: Have the AI look at several models that differ only in size and work out on its own which dimensions are parameters and how they relate.

  2. Load check: Use the generated part structure and material data to check whether furniture or stairs can bear the expected load.

  3. Code compliance check: Check whether the generated design meets building codes and related regulations.
