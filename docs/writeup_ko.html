초록

인테리어 설계와 맞춤 가구는 주문마다 치수가 달라, 보통 매번 도면과 3D 모델을 새로 그립니다. 저는 이 반복 작업을 없애려고 치수만 바꾸면 형상이 규칙대로 다시 만들어지는 파라메트릭 모델을 도입했고, 주문마다 다시 그리는 병목을 한 차례 해소했습니다. 하지만 파라메트릭 모델 자체는 여전히 제가 설계 규칙을 하나씩 넣어 만들어야 하고, 제품의 종류가 늘 때마다 이 작업이 다시 병목이 됩니다. 이 프로젝트는 고객의 말 한 문장으로 AI가 주방 하부장의 파라메트릭 CAD 모델을 만들 수 있는지 실험했습니다. 생성된 22개 모델은 고객이 요청한 크기에서 모두 규칙을 지켰고, 크기를 30가지씩 바꾼 638번의 검사에서는 98%가 통과했습니다. 실패한 2%는 문이 3짝일 때만 나타나는 경첩 방향 오류였으며, 고객이 요청한 크기 하나만 검사해서는 찾을 수 없는 오류였습니다.

사용 도구: Python, CadQuery, Claude API, GitHub Actions(자동 실행)

코드와 결과: github.com/goyodsgn/param-cabinet

1. 서론

1.1 문제

주방 가구는 설치할 공간에 맞춰 치수가 정해집니다. 같은 하부장이라도 폭, 높이, 깊이가 주문마다 다르기 때문에, 보통은 주문이 들어올 때마다 도면과 3D 모델을 새로 그립니다. 저는 이 반복 작업을 줄이기 위해 가구를 파라메트릭 모델로 설계하기 시작했고, 치수만 입력하면 형상이 나오도록 만들어 주문마다 다시 그리는 병목을 해소했습니다.

파라메트릭 모델이란: 치수(파라미터)를 바꾸면 형상이 정해진 규칙에 따라 자동으로 다시 만들어지는 3D 모델입니다. 예를 들어 하부장 폭을 늘리면 문 개수도 함께 늘어납니다.

남은 병목은 파라메트릭 모델을 처음 만드는 과정입니다. 하부장 하나에도 문 개수, 경첩 위치, 칸막이, 선반, 다리 배치 같은 규칙이 여러 개 있고, 이 규칙들은 서로 얽혀 있습니다. 폭이 바뀌면 문 개수가 바뀌고, 문 개수가 바뀌면 칸막이와 경첩 방향도 바뀝니다. 이 관계를 제가 하나씩 직접 정의해야 하고, 제품 종류가 늘 때마다 처음부터 다시 해야 합니다. 이 과정을 AI가 대신할 수 있다면 두 번째 병목도 줄일 수 있습니다.

1.2 연구 질문

AI가 만든 모델을 실무에서 파라메트릭 모델로 쓰려면 세 가지가 확인돼야 합니다.

  • RQ1. 고객이 말하는 방식이 달라도, AI가 치수를 정확히 읽고 규칙대로 모델을 만드는가?

  • RQ2. 고객 요청과 제작 규칙이 충돌할 때, 정해진 우선순위대로 처리하는가?

  • RQ3. 만들어진 모델에 다른 크기를 넣어도 규칙이 유지되는가?

RQ3이 이 프로젝트의 핵심입니다. 파라메트릭 모델은 나중에 크기를 바꿔 쓰려고 만드는 것이므로, 처음 요청한 크기에서만 맞는 모델은 쓸 수 없습니다.

2. 관련 연구

문장으로 3D 형상을 만드는 AI는 크게 두 종류가 있습니다. Mesh 생성 AI는 표면 조각(메쉬)으로 된 형상을 만들어 실물 생산에 활용할 수 없습니다. CAD 코드 생성 AI(text-to-CAD)는 실물로 생산 가능한 코드를 만들지만, 대부분 형상 하나가 설명대로 생겼는지만 평가합니다. 두 방식 모두 "크기를 바꿔도 규칙을 지키는가"는 다루지 않습니다. 이 프로젝트는 실물 생산을 위해 CAD 코드 생성 방식을 쓰되, 평가 기준을 이 질문으로 바꿨습니다.

3. 방법

3.1 실험 대상: 하부장과 설계 규칙

실험 대상은 주방 하부장입니다. 크기에 따라 문, 힌지, 칸막이, 선반 개수가 바뀌고, 외형의 디자인이 복잡하지 않아 파라메트릭의 구현도에 집중하기에 좋습니다. 입력은 폭(W), 높이(H), 깊이(D)이며, 문과 다리까지 포함한 최종 외곽 치수입니다.

표에 나오는 용어는 다음과 같습니다.

  • 온셋 / 인셋: 판을 다른 판의 끝면 위에 덮어 붙이면 온셋, 판과 판 사이에 끼워 넣으면 인셋입니다.

  • 도어갭: 문과 몸통, 문과 문 사이에 두는 틈입니다. 설치 오차로 문끼리 부딪히지 않게 합니다.

  • 선반 다보: 선반을 얹는 작은 받침 핀입니다. 칸막이 판에 구멍을 뚫고 끼워 넣습니다.

  • 내부 벽: 문 뒤쪽 공간을 나누는 세로 칸막이입니다.

규칙에는 우선순위를 두었습니다. 표의 "불가"는 힌지 하중이나 제작 오차 때문에 반드시 지켜야 하는 절대 규칙입니다. 고객이 다르게 요청해도 유지하고, 그 이유를 메모로 남기도록 했습니다. 나머지는 회사 기본값이며, 고객이 명시하면 고객 요청을 따릅니다.

3.2 구현 도구

코드 도구로는 CadQuery를 사용했습니다. 파이썬 코드로 3D 형상을 만드는 오픈소스 CAD 도구이고, 실무 CAD에서 열 수 있는 STEP 파일로 내보낼 수 있습니다. 코드 맨 위의 숫자(폭, 높이, 깊이 등)를 바꾸고 다시 실행하면 형상이 새로 만들어집니다. 즉 코드 자체가 일반 CAD 프로그램의 피처 트리 역할을 합니다.

3.3 실험 절차

AI가 만든 모델을 사람이 눈으로 확인하지 않고, 기준 모델과 자동으로 비교하도록 구성했습니다.

그림 1. 실험 흐름. 생성한 모델을 크기를 바꿔 가며 다시 채점하는 것이 핵심입니다.

  1. 기준 모델 만들기: 하부장 규칙을 모두 반영한 기준 모델(정답 모델)을 먼저 만들었습니다. 크기를 넣으면 문 몇 짝, 힌지 몇 개가 맞는지 계산해 줍니다.

  2. AI에게 주문하기: AI(Claude Sonnet 5.5)에게 회사 규칙 문서와 고객 문장을 주고 CadQuery 코드를 작성하게 했습니다.

  3. 채점하기: AI가 쓴 코드를 실제로 실행해 3D 형상을 만들고, 아래 12개 항목을 기준 모델과 비교했습니다.

  4. 크기를 바꿔 다시 채점하기: 같은 코드에 크기를 30가지로 바꿔 넣고, 매번 다시 채점했습니다. 고객이 나중에 치수를 바꿔도 모델이 깨지지 않는지 확인하는 단계입니다.

이 과정은 모두 GitHub Actions로 자동 실행됩니다. 코드를 올리면 서버에서 생성, 채점, 결과 이미지 생성까지 진행됩니다.

3.4 평가 지표

AI가 만든 모델을 기준 모델과 아래 12개 항목으로 비교했습니다. 하나라도 다르면 실패로 처리했습니다.

  • 들어줄 수 있는 요청 7건: 모두 고객 요청대로 만들었습니다.

  • 절대 규칙과 부딪히는 요청 5건: 모두 규칙을 지켰고, 고객에게 보여줄 수 있는 메모로 이유를 남겼습니다.

5. 논의

5.1 주요 발견

  • 규칙을 명확히 주면 AI는 규칙이 많고 고객 요청이 섞여도 잘 따릅니다.

  • 파라메트릭 모델은 크기를 바꿔 가며 검증해야 합니다. 한 가지 크기에서 맞아도 다른 크기에서는 틀릴 수 있습니다.

  • 규칙을 "고객이 바꿀 수 있는 것"과 "제작상 바꿀 수 없는 것"으로 나눠 주면, AI가 고객 요청을 반영하면서도 제작 조건을 지킵니다.

5.2 한계

  • 규칙을 미리 계산식으로 정리해서 주었습니다. 실제 현장에서는 규칙이 문서로 정리돼 있지 않고, 제작자의 노하우로만 존재하는 경우가 많습니다.

  • 대상은 하부장 한 종류이고, 서랍과 손잡이는 포함하지 않았습니다.

6. 결론 및 향후 연구

규칙을 명확히 정리해 주면, AI는 고객 문장 하나로 크기를 바꿔 쓸 수 있는 하부장 파라메트릭 모델을 98% 수준으로 만들 수 있었습니다. 동시에 한 가지 크기만 검사해서는 모델이 맞는지 판단할 수 없다는 점도 확인했습니다. 앞으로 진행할 작업은 다음과 같습니다.

6.1 이번 실험 보완

  1. 자동 수정: 실패한 사례를 AI에게 돌려주고 스스로 고치게 해서, 98%를 100%로 올릴 수 있는지 확인합니다.

  2. 웹 데모: 생성된 모델에 슬라이더를 붙여, 웹에서 치수를 바꾸며 형상을 바로 볼 수 있게 합니다.

  3. 규칙을 말로만 주는 실험: 계산식 대신 실무자가 말하듯 규칙을 주고, 그 순서도 섞었을 때 정확도가 얼마나 떨어지는지 측정합니다.

6.2 적용 범위 확장

  1. 연구 방향: 크기만 다른 모델 여러 개를 보고, 어떤 치수가 파라미터이고 치수끼리 어떤 관계인지를 AI가 스스로 찾아내게 하는 것입니다.

  2. 하중 검토: 생성된 부품 구성과 자재 정보를 바탕으로, 가구나 계단이 예상 하중을 견디는지 검사하는 기능을 추가합니다.

  3. 법규 검토: 생성된 설계가 건축법 등 관련 법규에 맞는지 검토하는 기능을 추가합니다.
